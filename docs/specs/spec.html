Hydrascale v1.0

One Linux host, several Tailscale tailnets, and an operator console that shows exactly what can reach what.

status: draft created 2026-08-04 branch model: dev-and-live repo: Crank-Git/Hydrascale 10 epics

Executive summary

Hydrascale lets one Linux host join several Tailscale tailnets at the same time. The daemon creates a network namespace per tailnet, runs a separate tailscaled in each, and reconciles the live host toward a declared YAML state.

Version 1.0 makes three changes:

  1. It removes the desktop client and replaces it with a console that the daemon serves on the loopback address.
  2. It gives the operator direct control over reachability — both the local rules the host enforces and the upstream policy each control server holds.
  3. It closes the gap between the isolation the documentation promises and the isolation the host enforces.

Why this release

The stated isolation is not enforced at the forwarding layer

For every namespace, internal/namespaces/ns.go:263 inserts this rule into the host FORWARD chain:

iptables -I FORWARD 1 -i vh<hash> -j ACCEPT

It matches on the input interface only — no destination, no output interface. Combined with a default route out of every namespace (ns.go:250), per-veth forwarding (ns.go:256) and a per-namespace MASQUERADE (ns.go:277), a process inside namespace A has a forwarding path to namespace B, to every peer route host access installs for B, and to the host local network. Because the rule is inserted at position 1, it also sits above any rule the operator's own firewall placed in FORWARD.

The README says "traffic from one tailnet never leaks into another." That holds for routing tables and separate network stacks. It does not hold for forwarding.

Confidence: this is a code read, not a demonstrated exploit. Reproducing it on the test host is the first task of Epic 2. If it does not reproduce, the spec says so.

That finding is why the visual access-control system is a security fix with an interface, rather than a feature with a graph.

Goals and non-goals

Goals

  1. A process in one namespace cannot reach another namespace unless a local rule allows it, and the operator can verify this on the test host.
  2. The operator can read and change reachability in the console, for local rules and for the upstream policy of each tailnet.
  3. The daemon reports when it cannot protect the host /etc/resolv.conf. It never fails to protect that file without a report.
  4. The repository contains no compiled binary, no desktop client, and no private development note.
  5. A configuration file that works on version 0.9 works on version 1.0 without an edit.
  6. The console, the command line interface, and the terminal interface all use the brand.

Non-goals

  • No account system and no transport security for the console. It serves loopback only.
  • No stability promise for the existing /api/* JSON shapes.
  • No Git history rewrite. Every commit, tag and fork keeps working.
  • No device, tag, user or key management through the upstream policy feature.
  • No non-Linux daemon.

Console stack, and why

The console is a static single-page application at internal/ui/static/, placed in the binary by go:embed. No build step, no package manager, no framework.

This beats a bundled framework on four counts: the offline vendored build survives, the release stays one artifact, continuous integration stays one toolchain, and the console loads no code from a network. The cost is a hand-written SVG renderer, and the brand's React components become a reference rather than a dependency. The same pattern already works in Nydus.

Fonts must not come from Google

The brand's tokens/fonts.css imports Space Grotesk and Space Mono from Google Fonts. An operator console for a network tool must not contact a third party, and the daemon must work with no internet route. Epic 6 either embeds both families as WOFF2 or falls back to system-ui and ui-monospace. Risk R4 tracks the licence check.

Data model

Configuration — additive only

Version 1.0 adds keys. It removes none and renames none. A v0.9 file loads unchanged.

# new in v1.0
console:
  enabled: true
  bind_address: 127.0.0.1:9443

access:
  # "enforce" applies the rule set. "observe" logs what it would deny and denies nothing.
  mode: enforce
  rules:
    - from: jbones
      to: homelab
      ports: ["tcp/22", "tcp/443"]
    - from: jbones
      to: host
      ports: []

secrets_file: /etc/hydrascale/secrets.yaml

Local rule

FieldTypeConstraint
fromstringA tailnet id, or the literal host.
tostringA tailnet id, host, or internet.
portslist of stringtcp/<n>, udp/<n>, or a range. Empty means every port.

A local rule allows. There is no deny rule — the daemon denies everything no rule allows.

Cross-cutting concerns

Accepted risk: the console has no authentication

Any local account, and any process it runs, can reach 127.0.0.1:9443 and drive a root daemon. This is the operator's decision and the spec states it plainly rather than implying it is safe.

Four controls reduce it, all in Epic 6:

  1. The listener binds 127.0.0.1 only; the daemon refuses any other address.
  2. Every mutating route requires X-Hydrascale-Console: 1, which a cross-origin form post cannot set.
  3. A request with a foreign Origin header is rejected.
  4. Every mutating request writes an event the console shows.

Controls 2 and 3 stop a hostile web page. Neither stops a local account. The spec does not claim otherwise, and the release note repeats it.

Other cross-cutting rules: the daemon stays root; socket_group membership is documented as equivalent to root; every os/exec argument from configuration or a request is validated; a best-effort operation that fails silently is treated as a defect; no log line carries an auth key or an OAuth secret; the topology has a text equivalent, because a dotted curve means nothing to a screen reader.

Risks and open questions

#ItemHow it resolves
R1The Tailscale OAuth scope for a policy write is unconfirmed. The OpenAPI schema names policy_file:read for the GET and names no scope for the POST.Epic 8 confirms it from the Tailscale OAuth docs before writing the setup guide. Until then the spec states no write scope name.
R2Headscale PUT /api/v1/policy succeeds only when the control server runs policy.mode: "db".Epic 8 detects the mode from the error and shows the reason. The local-file fallback is out of scope.
R3The DNS defect may not reproduce on the test host — the operator last saw it on a Jetson Orin with a Tegra kernel, and phobos is x86-64.Epic 4 opens with a reproduction attempt. If it fails, Epic 4 delivers detection and reporting rather than a targeted fix, and says so in writing.
R4The Space Grotesk and Space Mono licences must permit embedding in a binary.Epic 6 checks the SIL Open Font License terms; the fallback is system-ui and ui-monospace.
R5A local account can drive the root daemon through the console listener.Accepted by the operator. Epic 2 records it as a finding so it is written down; the release note states it.
R6The default-deny migration may cut off a path the operator does not know about.Epic 5 writes the preserving rule set on first start and records it. access.mode: observe lets the operator check before enforcement.
R7The rule engine must not fight ufw or firewalld.A dedicated chain with a single jump makes a reload detectable and repairable. Epic 5 verifies on the test host.
R8Should docs/specs/ be tracked in a public repository? The build loop needs tracked files; the operator wants planning artifacts private.Open — the operator decides in this review round.

Assumptions

  1. The operator accepts that hydrascale stays a root daemon on a trusted single-user host. The console threat model follows from that.
  2. The test host reproduces the reachability defect, because it follows from iptables rules rather than from a kernel feature.
  3. No external user depends on the JSON shape of the /api/* routes.
  4. dist/ and the root hydrascale binary are build output, not deliberate artifacts.
  5. The vendored build is not what the documentation claims. .gitignore line 24 ignores /vendor/ and git ls-files vendor returns nothing, so no clone carries the vendored dependencies and no clone builds offline. Epic 0 makes the repository and the claim agree.
  6. Version 1.0 writes IPv4 local rules only. Epic 2 confirms whether an IPv6 gap exists; Epic 5 logs the gap at start rather than hiding it.
  7. 9443 is free on a typical host, and the configuration can change it.

Full detail lives in spec.md and the ten files under features/.
